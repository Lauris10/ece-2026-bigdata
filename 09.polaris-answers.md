# Lab 09 : Polaris, gouvernance des tables Iceberg

## Session Spark et catalogues
- `SHOW NAMESPACES IN lab` est répondu par le catalogue Hadoop (Spark lit directement les métadonnées dans S3). `SHOW NAMESPACES IN polaris` est répondu par le serveur Polaris via l'API REST Iceberg.
- Le credential du principal (`dev` ou `analyst`) sert uniquement à obtenir un jeton OAuth auprès de Polaris. Les données restent lues et écrites par Spark dans S3 avec les clés S3 de l'utilisateur.

## Enregistrement de silver.orders
- `register_table` n'écrit ni ne copie aucune donnée : il enregistre dans Polaris un pointeur vers `v1.metadata.json` existant. Résultat : 2829 commandes lues via `polaris.silver.orders` (même table que dans `lab`, un seul snapshot).
- Écrire ensuite via le catalogue `lab` est risqué : Polaris garde un pointeur vers l'ancienne version de métadonnées, et un commit fait en dehors de Polaris n'est pas vu par lui.

## Création de silver.users en tant que dev
- Les fichiers de `silver.users` créée via Polaris sont dans le même bucket, sous `warehouse/silver/users/` (données Parquet et métadonnées).
- Enregistrer reprend une table existante sans toucher aux fichiers ; créer via Polaris produit de nouveaux fichiers et une table gérée par Polaris dès le départ.

## Changement de schéma en tant que dev
- L'ajout de `country` crée un nouveau fichier de métadonnées (`00001-....metadata.json`) qui enregistre le nouveau schéma. Polaris vérifie le privilège de gestion des métadonnées de la table (`TABLE_WRITE_PROPERTIES` / `CATALOG_MANAGE_METADATA` du rôle `catalog_contributor`).

## Lecture en tant qu'analyst
- La lecture marche (`SHOW TABLES`, `GROUP BY product`). L'`INSERT` et l'`ALTER TABLE` sont rejetés par `ForbiddenException` : le rôle `data_analyst` n'a que des privilèges de lecture (`TABLE_READ_DATA`, `TABLE_READ_PROPERTIES`, `CATALOG_READ_PROPERTIES`), pas de privilège d'écriture ni de gestion.
- L'`INSERT` refusé n'a créé aucun snapshot : `silver.orders` reste à 1 snapshot.

## Exercice 1 : supprimer la colonne country
- `ALTER TABLE polaris.silver.users DROP COLUMN country` n'ajoute aucun snapshot (toujours `8306032244380486853`, `overwrite`). C'est une opération de métadonnées : seul le schéma change dans un nouveau fichier de métadonnées ; les fichiers Parquet ne sont pas réécrits.

## Exercice 2 : rôle silver_reader
- Via l'API de gestion de Polaris : catalog role `silver_reader` avec `NAMESPACE_LIST`, `NAMESPACE_READ_PROPERTIES`, `TABLE_LIST`, `TABLE_READ_PROPERTIES`, `TABLE_READ_DATA` sur le namespace `silver` uniquement ; principal role `silver_reader_role` ; principal `silver_user`.
- Test avec `silver_user` : `SELECT count(*) FROM polaris.silver.users` renvoie 50 ; `SHOW TABLES IN polaris.gold` (namespace créé par dev) est refusé (`ForbiddenException`), comme `SHOW NAMESPACES IN polaris` au niveau du catalogue.

## Nettoyage
- `polaris.silver.users` et le namespace `polaris.gold` sont supprimés ; `silver.orders` reste enregistrée pour le lab Trino.
